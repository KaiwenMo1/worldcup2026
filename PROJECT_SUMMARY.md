# World Cup 2026 Forecast Lab: Project Summary

## One-Sentence Summary

An end-to-end football analytics application that trains a calibrated match-outcome ensemble, predicts exact scores, simulates the 48-team World Cup, updates forecasts with fixture and live context, and explains results through an evidence-backed analyst interface.

## What The Project Demonstrates

This is more than a winner predictor. It demonstrates how to turn a machine-learning model into an inspectable analytical product:

- **Machine learning:** Random Forest result and goal models, Dixon-Coles score modeling, Elo probabilities, calibration, and chronological evaluation.
- **Probability modeling:** normalized exact-score distributions whose cells aggregate into the displayed win/draw/loss probabilities.
- **Simulation:** Monte Carlo execution of the new 48-team format, including 12 groups and the eight best third-place qualifiers.
- **Feature engineering:** leakage-safe historical form, strength, rest, experience, and confederation features.
- **Forecast-time context:** squads, projected or confirmed lineups, availability, tactics, weather, travel, fatigue, set pieces, referees, market signals, and live results.
- **Product engineering:** FastAPI backend, interactive sports dashboard, CLI workflows, automated tests, CI, optional provider adapters, and a local RAG analyst.

## Verified Scale And Results

Current repository and saved-model facts:

- 48 teams across 12 groups.
- 104-match fixture-aware tournament structure.
- 7,952 historical matches split chronologically:
  - 4,771 training matches.
  - 1,597 calibration matches.
  - 1,584 holdout matches from October 8, 2024 through March 31, 2026.
- Current ensemble holdout performance:
  - `59.8%` match-outcome accuracy.
  - `0.863` multiclass log loss.
  - `0.506` Brier score.
  - `0.337` ranked probability score.
- The ensemble outperforms the saved Random Forest, Dixon-Coles, and Elo components on the holdout log loss and ranked probability score.

These figures are generated by the current local saved model and should be refreshed after retraining.

## End-To-End Flow

1. Historical international results are converted into chronological, leakage-safe training features.
2. Random Forest, Dixon-Coles, and Elo components produce match-result probabilities.
3. A calibration model combines the components.
4. Goal expectations become a normalized exact-score distribution.
5. Forecast-time context adjusts predictions without leaking future information into training.
6. Monte Carlo simulation produces advancement and champion probabilities.
7. FastAPI exposes forecasts, live-state updates, model reports, and evidence-backed analysis to the dashboard.

For the component map and design tradeoffs, see `docs/ARCHITECTURE.md`.

## User-Facing Workflows

- Run one tournament path or thousands of simulations.
- Inspect champion odds and confidence ranges.
- View a full bracket with teams, flags, and predicted scores.
- Predict any matchup and inspect exact-score probabilities.
- See which model and contextual inputs changed a forecast.
- Generate an analyst brief backed by local project evidence.
- Lock completed matches and eliminated teams so later simulations reflect the live tournament.

## Main Technical Decisions

### Chronological validation

Training, calibration, and test periods are separated by date. This better represents forecasting future matches than a random train/test split.

### Score-first probability model

The app generates a coherent score matrix and derives match probabilities from it. This prevents the exact-score display from disagreeing with the result probabilities.

### Historical versus forecast-time features

Historical features are built only from information available before a match. Dynamic signals such as weather, confirmed lineups, and live results are applied at forecast time.

### Local-first operation

The CLI, website, and RAG analyst work without paid APIs. Optional providers can replace projected fallback data with observed information.

### Inspectable analysis

The Intelligence Desk retrieves local evidence, routes questions to football-specific tools, returns citations, and exposes an agent trace. Optional LLM synthesis is an enhancement rather than a requirement.

## How To Run

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

python scripts/predict_worldcup.py --sims 1000 --seed 26
python -m unittest discover -s tests -v
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Train and inspect the ensemble:

```bash
python scripts/train_model.py
python scripts/backtest_models.py
```

## Honest Limitations

- Some player, squad, tactical, and availability features are projected fallbacks rather than observed licensed data.
- The shot-level xG and penalty datasets are much smaller than the historical match dataset.
- The current JSON live-state store targets local use and is not safe for concurrent production writers.
- `app/main.py` currently centralizes many orchestration responsibilities and is the next architectural extraction point.
- Forecasts are probabilistic research outputs, not guaranteed outcomes or betting advice.
